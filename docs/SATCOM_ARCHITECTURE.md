Updated September 7, 2026. The publisher confirmed `satcom.conews.press` as the target for this task. The original `satcom.copress.press` does not resolve; no DNS changes were required.

The local checkout also contained an unmerged receptionist MCP draft and campaign work. This release starts from remote main and does not merge or activate those drafts. Public MCP has no send, deployment, secret, arbitrary-fetch, subscriber or telephony capability.

## MCP contract

Endpoint: `https://satcom.conews.press/mcp`. The direct `/api/mcp` handler exposes the same service. Authentication is not required because every response is reviewed public information already published under `/data/codex/`. This is not an authentication bypass for another backend. Any future private or mutating capability needs a separately scoped, authenticated design.

| Feature | Name | Scope |
|---|---|---|
| Tool | `satcom_structure` | Dated structure, route map and boundaries |
| Tool | `satcom_priorities` | Ten public priorities, owner, target window, next action; Partners primary |
| Tool | `satcom_prompt` | Enum: `grok-development`, `satcom-release`, `partners-editorial` |
| Resource | `satcom://context` | Curated public JSON |
| Prompts | Same three names | User-selectable reviewed prompts; no dispatch |

All tools advertise read-only, non-destructive, idempotent and closed-world annotations. Input cannot select a filesystem path or URL. Browser Origins are allowlisted; native clients without Origin are supported. Requests require JSON and the MCP Accept headers. A GET to `/mcp` intentionally returns 405 (POST supported, no standalone SSE stream); use `/api/health` for a simple service response. Responses are not cached. Neither health nor public context asserts live provider connectivity.

## Connect and verify

```sh
codex mcp add satcom --url https://satcom.conews.press/mcp
npm ci
npm run build
npm test
npm run verify:mcp -- https://satcom.conews.press/mcp
```

Restart/reload a client that does not refresh its configured MCP list. The verification script uses the official SDK client: initialize, tools/list, three read-only tool calls, resources/list + read, prompts/list + three prompt reads. Configuration alone is not proof of connection.

For local development, `npm run dev` serves `http://127.0.0.1:4321`; run `npm run verify:mcp` against that default. Browser health checks are limited to this service. Review `/codex` at desktop/mobile widths, keyboard navigation, copy feedback and prompt overflow. `npm test` verifies real SDK requests, parallel clients, input rejection, allowed capabilities, health semantics and preserved routing. `npm run build` refreshes the committed static page from the same reviewed content used by MCP; rebuild after any prompt/context edit.
