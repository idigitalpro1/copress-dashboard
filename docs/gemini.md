# Shared Gemini client (0.2.0, preview only — do not merge)

Vercel / SATCOM Video Studio side only. Subscribe, Stripe, checkout, postcard QR routes, WordPress and DNS are unchanged. This PR does not change Vercel project settings or apply SQL to a live Supabase project.

Omni **generation** is still out of this repo. **Reviewed publishing** (YouTube + satcom.conews.press/video) is a stacked preview on this branch; see [youtube.md](youtube.md) and [video-studio.md](video-studio.md). Do not merge.

Stacked on draft PR #32 (`cursor/gemini-shared-client-86da`), which is stacked on draft PR #29 (`cursor/video-studio-preview`). Preview env only. This publish PR must not be merged.

Patrick Sweeney owns, on his own server:

- the Python Gemini client
- three isolated keys (`GEMINI_KEY_VIDEO`, `GEMINI_KEY_COPY`, `GEMINI_KEY_HEALTH`)
- the async Omni video generation queue
- `publish_gate` validators

This repo does **not** ship a Python twin, does **not** submit Omni jobs, and does **not** poll Gemini. It lists and opens finished clips that Patrick's queue deposits in Cloudinary.

## Module

Version **0.2.0** lives in `packages/satcom-gemini/` (`VERSION`, `CHANGELOG.md`, `registry/models.json`). Other projects pin a git commit or tag. The JS module calls `generateContent` for the **copy** workload (captions, titles, descriptions). `generateContent` refuses the video/Omni workload.

### No `GEMINI_API_KEY` fallback

`GEMINI_API_KEY` is **not read**. The earlier Video Studio preview (PR #29) used that single name for Gemini assist. On this stacked branch, Studio Gemini assist and Gemini transcription require `GEMINI_KEY_COPY`. A missing copy key disables those buttons; it does not fall back to a shared key. That is intentional so copy cannot spend Patrick's video key.

SQL files in `supabase/migrations/` are **in the repo only**. They have not been applied. An operator must review and apply `gemini_usage` and `gemini_circuit` to a Preview Supabase project — not production. There is no `video_jobs` table. If a 0.1.0 Preview project already applied `video_jobs`, that table is unused and may be dropped by an operator.

`CRON_SECRET` is unused here. There is no `/api/gemini/poll` route and no `crons` entry in `vercel.json`.

## Handoff contract (Patrick's queue → Studio)

Patrick's server generates the clip, then uploads a **private** Cloudinary draft. The Studio only **lists** and **opens** those drafts (`op: generated-list`, `op: generated-get`). Publishing stays a separate reviewed step.

| Field | Value |
| --- | --- |
| Video folder | `satcom/generated` |
| Originals folder (do not overwrite) | `satcom/paul-hill/originals` |
| Resource type | `video` (sidecar: `raw`) |
| Delivery type | `private` |
| `published` | `false` |
| Video tags | `satcom-generated`, `ai-generated`, `gemini-omni`, `draft` |
| Sidecar tags | `satcom-generated`, `ai-generated`, `sidecar`, `draft` |
| Sidecar public id | `{video_public_id}-sidecar` |

Sidecar JSON (canonical fields; extra keys are ignored):

```json
{
  "model": "gemini-omni-1.1-flash",
  "prompt": "…",
  "resolution": "1080p",
  "duration": 8,
  "aspect": "16:9",
  "timestamp": "2026-09-29T20:00:00.000Z",
  "synthid_note": "This video was generated by Google Gemini Omni Flash. All Google AI generated videos carry an invisible SynthID watermark for provenance. Label it as AI-generated wherever it is used."
}
```

`model` must be an allowed or optional video id (`gemini-omni-1.1-flash`; optional Veo ids). `gemini-omni-flash-preview` is denied. Native Omni output is 720p; request 1080p (upscaled) and write that in `resolution`.

Same contract is pinned in `packages/satcom-gemini/registry/models.json` → `handoff`.

Studio ops:

1. `{ op: "generated-list" }` — Cloudinary search of private videos in `satcom/generated/`
2. `{ op: "generated-get", public_id: "satcom/generated/…" }` — signed private preview plus sidecar JSON
3. Opened clips may be used as a Studio source (`type: "private"` only when `public_id` starts with `satcom/generated/`)

## Recommended billing hard caps

Patrick's Gemini **consumer / Google AI Studio subscription does not cover API charges.** Omni Flash is paid-tier only (~$0.10/s of 720p; 1080p is upscaled at the same listed rate). Caps live on **Patrick's** GCP billing for video. This Vercel app only spends `GEMINI_KEY_COPY` when Studio Gemini assist/transcription runs.

Set a **Google Cloud billing-account hard cap** (cannot be overridden by this app):

| Cap | Amount | Why |
| --- | --- | --- |
| Billing account hard cap | **$150 / month** | Stops a leaked key or runaway loop |
| GCP project · video | $100 / month | Omni is the expensive path (Patrick's server) |
| GCP project · copy | $40 / month | Studio captions/titles |
| GCP project · health | $60 / month | Isolated from video |

In-app rolling caps (second line of defense only), from the registry:

- video: $15 / 24h, $100 / 30d, 4 requests/min (enforced on Patrick's server; this module does not call Omni)
- copy: $5 / 24h, $40 / 30d, 20 requests/min
- health: $8 / 24h, $60 / 30d, 30 requests/min

A runaway copy loop cannot spend the health key or close the health circuit.
